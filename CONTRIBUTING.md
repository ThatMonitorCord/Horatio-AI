# Contributing to my project hub

I use this repository for the website and public engineering documentation. I review changes here separately from application development.

## My publishing boundary

I accept capability explanations, architecture diagrams, synthetic examples, sanitized release notes and dated verification summaries. I exclude application source, packaged downloads, model identities, credentials, private records, operational addresses and private repository links. I use neutral descriptions for specialist agents without implying that all execution happens on one machine.

## My review checklist

1. I trace factual claims to dated engineering evidence and distinguish implemented, tested and planned behavior.
2. I update both HTML chapters and their Markdown companions. I keep the roadmap and journal consistent with the homepage.
3. I check local links, keyboard navigation, mobile layouts, contrast and release search. I preserve the mascot, self-hosted typography and flat reading surfaces.
4. I review the diff and reachable history for private material. I check release attachments and hosting settings separately.
5. I prepare a review branch. I do not change repository visibility or enable hosting as part of a documentation edit.

I write in the first person as the sole developer. I describe concrete behavior and its limits, avoid invented performance claims, and retain Horatio’s humor without inventing quotations from him.

I welcome specific bug reports without private logs, conversation excerpts or credentials.
